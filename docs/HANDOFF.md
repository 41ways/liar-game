## 3. 세 모드 규칙

공통: 폰을 돌려 제시어 확인 → START부터 한 마디씩 설명(한두 바퀴) → 동시에 손가락으로 지목 → 가장 많이 지목된 사람을 앱에 입력 → 라이어면 마지막으로 제시어를 맞힐 기회 → 맞히면 라이어 역전승. 동점이면 동점자끼리 변론 후 재지목(앱 안내 문구).

- **라이어 게임**: 라이어는 제시어 대신 주제만 본다. 라이어는 첫 발언자가 되지 않는다.
- **바보 라이어**: 라이어도 같은 주제의 다른 단어를 받는다. 화면 모양이 시민과 똑같아 본인은 모른다. 라이어가 여럿이면 같은 가짜 단어를 받는다.
- **스파이 게임**(사용자가 직접 설계한 규칙): 스파이만 다른 단어(본인도 모름). 질문이 나오면 1~10을 동시에 낸다(손가락 또는 폰 돌리기 모드의 '몰래 입력'). 질문은 라운드당 최대 3개. 결과 화면에 두 단어의 예상값(▲)과 실제 답 분포를 보여준다.

옵션(로비의 '규칙 옵션'):
- 라이어(스파이) 수 1~3명: `maxLiars(n,acc)` = 시민이 라이어보다 많도록 제한. 한 명씩 지목하고 잡힌 라이어마다 정답 기회. 모두 잡아야 시민 승리, 시민(또는 공범)을 지목하면 즉시 라이어 승리.
- 공범(라이어 게임, 5명 이상): 제시어를 알고 라이어 편, 라이어가 누군지는 모름.
- 라이어 힌트(라이어 게임): 제시어 글자 수(공백 제외).
- 라운드 미션(라이어·바보): `MISSIONS` 중 랜덤, null이면 자유 설명. '거꾸로 돌기'는 발언 순서를 실제로 뒤집는다.
- 토론 시간 1/2/3/5분, 벌칙(진 쪽에 `PENALTIES` 랜덤).
- 점수: 시민 승 → 시민 모두 +1 / 라이어 승 → 라이어 +3, 공범 +2. 이 점수 규칙은 원작에 근거가 없는 우리 규칙이다.

### 원작 대조 (LIAR GAME, LiarLiar 앱 설명 기준)
- 원작에 있고 넣은 것: 기본 진행, 바보 모드, 라이어 수, 스파이 모드(→ 우리 이름 '공범'. 우리에겐 이미 '스파이 게임' 모드가 있어서), 나만의 주제, 벌칙, 정답 힌트, 제한 시간, 발언 제약(→ 미션).
- **확인 못 해서 안 넣은 것**: 앱들의 '아이템 모드', '카오스 모드'(공개된 규칙 설명이 없음). 공범이 라이어를 아는지도 원작 설명에 없어서 '모른다'로 정했다.

## 4. 각자 폰 모드와 코드

서버 없이, 같은 코드를 넣은 폰들이 같은 시드로 같은 라운드를 각자 계산한다.

- 코드 6글자 = 30비트: 모드 2 · 인원-3 4 · 주제 6(63=랜덤) · 옵션 5 · 시드 13 (`encode`/`decode`, 글자표 `ABC`는 헷갈리는 0/O/1/I 제외)
- 옵션 5비트: 스파이 = 난이도 2 + 스파이 수-1 2 / 라이어·바보 = 미션 1 + 힌트 1 + 라이어 수-1 2 + 공범 1
- **주의 1**: `LIARC`/`SPYC`의 주제 순서, 단어 순서, 질문 순서, `MISSIONS`/`INTROS` 순서, 그리고 `genRound`의 난수 사용 순서를 바꾸면 버전이 다른 폰끼리 결과가 어긋난다. 데이터를 고친 뒤엔 모두 새 파일로 열어야 한다.
- **주의 2**: 코드 형식을 바꾸면 예전 코드가 무효가 된다(5자리 → 6자리로 이미 한 번 바꿈).
- 지목 결과·점수는 입력한 폰 한 대에만 남는다(서버가 없어서). 다음 라운드는 각자 ▶.
- '내 주제'는 기기에만 있으므로 폰 돌리기 모드 전용(`cfg.local`일 때만 `CUSTOM`을 붙임).
- 폰 돌리기 모드는 최근 단어를 피한다(`localStorage` `liar.recent`). 각자 폰 모드에선 결정성 때문에 쓰지 않는다.

localStorage 키: `liar.cfg`, `liar.mute`, `liar.recent`, `liar.custom`, `liar.own`(이어하기), `liar.v2`.

## 5. 스파이 질문·간극 데이터 만드는 법

`SPYC` 각 주제: 질문 10개 `[질문, 1점 쪽 설명, 10점 쪽 설명]` + 단어마다 `이름:값10개` (그 단어를 받은 **보통 사람이 낼 법한 평균 답**).

출제(`spyCands`):
1. 같은 주제의 모든 단어 짝에 대해 질문별 차이(간극)를 구한다.
2. 전체 평균 차이가 `DIFFS[d].sim`보다 크면 버린다(전체적으로 닮은 짝만 → 다른 질문에선 자연스럽게 섞이고 한 질문에서만 튐).
3. 첫 질문 = 간극이 난이도 범위(쉬움 6~9 / 보통 4~5 / 어려움 2~3)인 것.
4. 추가 질문 2개 = 간극이 max(2, 하한-1)~상한+1. **쓸 만한 질문이 3개가 안 되는 짝은 버린다.**
5. 주제·난이도마다 짝 100~350개.

단어를 추가할 땐 같은 주제의 비슷한 단어와 값을 나란히 놓고 맞춰 볼 것. 값은 전부 감으로 넣은 것이라 실제 플레이로 다듬어야 한다.

## 7. 시험 요령

- 브라우저 확인은 **항상 소리를 끄고**: `localStorage.setItem('liar.mute','true')` 후 새로고침.
- 내장 브라우저 창이 숨겨져 있으면 setTimeout이 거의 멈춘다 → 흐름 테스트는 타이머를 기다리지 말고 `G.pi=i; go('pass'); flipCard()`, `G.accused=i; go('caught')`, `wrongGuess()`, `finish('l')` 를 직접 호출.
- 스크린샷 전엔 애니메이션을 끄는 style을 넣는다: `*{transition:none!important;animation-duration:0s!important;animation-delay:0s!important}`. 그래도 첫 스크린샷은 이전 화면일 때가 있어 한 번 더 찍는다.
- 점검 항목: 화면 텍스트에 `undefined/NaN/[object` 없음, `genRound` 규칙(라이어 수·공범 겹침·라이어 첫 발언 금지·바보 단어 같은 주제·스파이 간극), `decode(encode(cfg))` 왕복.
- 테스트 후엔 `liar.recent`, `liar.cfg`, `liar.custom`, `liar.own` 을 지워 사용자 화면을 깨끗하게.
